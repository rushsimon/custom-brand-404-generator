# Preview report structure

Use the user's language. Deliver a concrete selected proposal, without suggesting that files were changed or checks were run. Show multiple concepts only if requested.

404 Design Preview — No project files changed

Creative Concept: [selected name]
[Premise and observed brand/product/scenario evidence; explain why this is native.]

Proposed Experience:
[Composition using the site's visual grammar, actual proposed headline/supporting copy/CTA labels, verified recovery destinations, optional interaction and reduced-motion/static behavior. State language/locale scope and asset reuse. If essential imagery is unavailable, include a complete image-generation prompt plus fallback.]

Implementation Plan:
[Native entrypoint/components, expected minimal file changes and HTTP-status approach, based on inspected repository. If none is identifiable, state that limitation.]

Validation Plan:
[How status, recovery, responsive, assets, accessibility, build and applicable analytics would be checked. These checks have not been executed on an implementation.]

Assumptions / Manual Decisions:
[Only meaningful uncertainties or indispensable missing target details. Otherwise None.]

Do not automatically request approval or implementation confirmation. Preview is the user's requested stopping point.
