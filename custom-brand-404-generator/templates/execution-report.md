# Execution report structure

Adapt labels and language to the user. This is a reporting structure, never a page design template. Replace fields with observed results; omit irrelevant feature bullets. Keep it concise by grouping audit items, not by hiding unverified checks.

404 Page: [Completed / Implemented with verification limits / Blocked]

Creative Concept: [name]
[1–3 sentences: premise, brand/product evidence and why it fits.]

Key Features: [recovery routes, chosen expression/interaction, locale coverage]

Change Audit:
- Files Added: [paths + reasons, or None]
- Files Modified: [paths + reasons, or None]
- Dependencies Added: [names + reasons, or “No new dependency added.”]
- Assets Added: [paths + reasons, or None]
- Routes Modified: [route/integration + reason, or None]
- Tracking Added: [events, parameters, implementation method, or None + reason]

Validation:
[For routing and HTTP status, recovery/search/links, assets, frontend/build, responsive, accessibility and applicable tracking: Passed / Failed / Not Verified, with concise evidence and environment. Group only results with the same status. Include commands/response statuses where helpful.]

Detected Differences / Decision Made: [material live/repository discrepancy, if any]
Manual Review / Blockers: [only actual unresolved needs, or None]

Only on explicit request for a detailed report add full brand/design analysis, candidate concepts/scores/rejections, technical decisions, tracking design, risks and future improvements. Do not expose all candidates by default.
